# 立法院公報詢答語料

## 來源代號

`tw-ly-transcript`

## 資料層

專案詞庫

## 狀態：已停用（2026-07-29）

本來源不再匯入 release，亦已自 manifest 移除。

停用依據：修復 65 筆綁在 `nq` 讀音的 `得`／`部份` 資料列後（該批列會與「的」互相搶位，修復使口語淨值由 15,460 升至 20,507），本層在 `chiaki-tw-homophone-bigram` 之上的邊際貢獻仍為書面 +0.07%、口語 −0.6%、PTT −0.5%、訊息 −0.5%。兩層取材同一批立法院公報，但後者的選材判準涵蓋了本層 89% 的獨有配對所在位置（詳見該來源〈與既有來源的關係〉）。

`bigrams.tsv`、`review-decisions.tsv` 與下方研究附錄保留供追溯，附錄記錄的語域切分、議事語域偏誤分析與讀音問題仍是有效的方法論紀錄，且該批人工複核判定可在需要時重新沿用。

## 用途與定位

此來源收錄從立法院公報詢答段落萃取、經自動過濾與人工複核的 bigram 資料。

公報逐字稿是目前可取得的語料中，少數同時具備「真實即席口語」「台灣本土語境」「授權可再散布」三個條件的來源。專案只散布最終萃取的詞庫列，原始公報文字不在本專案再散布。

## 檔案與格式

`bigrams.tsv`：

```text
qstring<TAB>previous<TAB>current<TAB>probability
```

`review-decisions.tsv`：人工複核紀錄，第一欄為 `keep` / `drop`，供重新產生資料列時沿用既有判斷。格式與 `scripts/corpus/postprocess-ly-bigrams.mjs` 的 `--review` 輸出相同。

## Release 匯入規則

匯入位置在 `openformosa-common-voice-25-zh-tw` 之後、`chiaki-web-overlay` 之前。web overlay 為人工審查來源，其判斷應保留在本層之上。

Bigram 以條件強度序匯入，並在 release 階段重新錨定到當前 unigram floor：

```text
stored = min(unigram(current) + boost + (raw - raw_max_of_source), -0.05)
```

- 預設 `boost`：`1.5`
- 覆寫環境變數：`TW_LY_TRANSCRIPT_BIGRAM_BOOST`
- 設為 `0` 時：保留原始數值

`probability` 欄位是**來源內部的強度序**，不是條件機率。原始統計工具輸出的是常數，實際強度由 `doc_count` 經 log 映射到 `[-1.7, -0.2]` 得出（見〈研究附錄〉）。

## 研究附錄：公報詢答語料的萃取與過濾方法

### 摘要

本附錄記錄從立法院公報建立 bigram 來源的完整方法，包含語域切分、頻率換算、系統性偏誤過濾與人工複核流程。核心發現是：公報語料中**訊號最強的搭配恰好是最沒有價值的部分**，因此過濾設計的重點不在提高門檻，而在辨識並移除語域偏誤。

### 研究問題

1. 公報文件混雜多種文體，如何在不建分類器的前提下只取出口語詢答？
2. 純文字語料缺乏讀音資訊，對注音輸入法的 bigram 有何結構性限制？
3. 議場語域相對於日常輸入的系統性偏誤有哪些，可否機械化辨識？
4. 哪些過濾判準可由資料導出，哪些只能靠人工判斷？

### 資料來源與規模

| 項目           | 數值                              |
| -------------- | --------------------------------- |
| 索引議程數     | 7,042（第 10、11 屆）             |
| 實際下載       | 4,037 份（其餘因 API 限流未取得） |
| 上游轉檔失敗   | 11 份，記錄於 `failures.json`     |
| 原始字數       | 247,792,469                       |
| 萃取後發言輪次 | 1,192,984                         |
| 萃取後字數     | 66,620,767（保留率 26.9%）        |

### 語域切分

一份公報通常混雜四種文體，其中只有一種對輸入法有用（以第 11 屆外交及國防委員會第 24 次會議紀錄為例）：

| 文體         | 特徵                                  | 處置     |
| ------------ | ------------------------------------- | -------- |
| 議事錄       | 出席名單、時間地點，全形空格排版      | 丟棄     |
| 預算決議     | 「爰凍結該項預算50萬元，俟…始得動支」 | 丟棄     |
| 專案書面報告 | 壹、貳、參編號的講稿本文              | 丟棄     |
| 詢答對話     | 委員與官員的即席問答                  | **保留** |

判準：**只有「發言人：內容」這種行才是詢答**。書面段落一律沒有發言人前綴，所以這一條規則同時擋掉前三種，不需要另外建段落分類器。議事錄的標籤行（`主　　席：`）以全形空格撐開版面，可據此與真正的發言人行區分。

驗證方式為對混合四種文體的真實文件進行檢查：議事錄、預算決議、報告本文、名單全數正確丟棄，詢答輪次全數保留；純議事錄文件輸出 0 列。

初版實作有兩個缺陷，由抽樣檢查發現：

- **機關標籤誤判**：`程序委員會意見：擬請院會將本案交經濟委員會審查。` 的格式與發言人行完全相同，混入 66,420 筆。修正方式為排除含「委員會」的發言人，人名不會含此字串（委員寫作「陳委員椒華」，主委寫作「陳主任委員吉仲」）。
- **短句重複無上限**：單一句「擬請院會將本案交經濟委員會。」出現 11,711 次。原設計只對 20 字以上發言去重（理由是短語高頻為真實訊號），未預期此量級。修正為短句保留上限 20 次。

### 頻率換算

`build-bigram-stats` 的 `--probability` 是常數（預設 `-0.1`），所有列取得相同數值。由於 release 的 calibration 計算 `(raw - raw_max)`，raw 全部相同即等於整批平權，出現 10,059 篇的搭配與出現 17 篇的無法區分。

本層改用 `doc_count` 做單調映射：

```text
raw = CEIL - SPAN × log(maxDoc / doc) / log(maxDoc / minDoc)
```

- 採 `doc_count` 而非 `count`：同一篇文件內重複 50 次不等於 50 篇文件都出現。實測 `count > 3 × doc_count` 的列為 0，語料本身無單篇灌水問題。
- `SPAN` 預設 `1.5`，對齊 boost 的作用窗寬度，避免任何列單純因校準被擠到 unigram floor 以下。

`stats` 檔僅含 `selected` 列，不含 `redundant` 與各類 excluded，因此同一 `previous` 的 count 總和不是真正的邊際分布，無法計算 P(current|previous)。輸出值定位為來源內部強度序而非條件機率；calibration 只使用相對差距，此近似為充分。

### 門檻選擇

`doc_count` 分布（91,021 筆 selected）：中位數 5、p75 為 9、p90 為 20、p99 為 139。

門檻取 `17`。此值由相對頻率推導：初次評估在 2,371 份文件的基礎上採用 `10`，文件數增加至 4,037 份（1.70 倍）後等比例調整為 17，以維持相同的相對出現率。實測顯示提高門檻不改變靶準度，`doc_count ≥ 3` 時有 73.0% 的列落在有同音對手的讀音上，`≥ 20` 時為 74.6%，門檻的作用是移除薄尾而非改善選材。

### 系統性偏誤過濾

公報語料 `doc_count` 最高的搭配為：條文+通過、審查會+條文、案+通過、所以+本席、本席+要。**訊號最強的部分恰是議場專用語域**，價值集中在中頻帶。此分布與一般語料的直覺相反，是本來源過濾設計的主要依據。

| 判準              | 移除  | 說明                                                       |
| ----------------- | ----- | ---------------------------------------------------------- |
| 議事語域 denylist | 748   | 本席、審查會、逕付、朝野協商、異議、議事、裁示、及第、委員 |
| 稱呼殘骸          | 272   | `謝謝`／`感謝` 為 previous，或單字姓氏為 current           |
| 讀音改掛          | 37    | 見〈讀音問題〉                                             |
| 數字序數          | 159   | token 全由數字字元構成（千萬／萬一／一一 例外）            |
| 姓+職稱           | 132   | 「請邱委員議瑩發言」的殘留                                 |
| 單字碎片          | 906   | 單字 current 且 unigram 權重 < -1.2                        |
| 偏誤字元替換      | 1,241 | 見下                                                       |
| 讀音存疑          | 298   | 見〈讀音問題〉                                             |
| 人工複核判定      | 95    | `review-decisions.tsv`                                     |

**「議」系會議詞**（異議、無異議、議事、動議）需特別說明。這批詞的同音對應（意義、無意義、意識）在日常用法遠更常見，語料的偏好會破壞高頻日常詞。此判準無法由權重落差導出：實測 `議事`／`意識` 落差 0.759 應移除，而 `邱泰源`／`太原` 落差 0.87 卻是正確的人名消歧；`無異議`／`無意義` 落差 0.010 應移除，而 `保育`／`寶玉`、`條文`／`條紋` 落差同為 0.010 卻應保留。差別在語義語域而非頻率結構，因此採點名而非門檻。

**偏誤字元替換**以「詞庫預設字→語料選字」的形式點名，由資料導出：將所有「同長度、差一字」的替換依累積 `doc_count` 排序後，偏誤與正確修正可清楚區分。

| 替換  | 列數 | 判定                                               |
| ----- | ---- | -------------------------------------------------- |
| 台→臺 | 467  | 異體字，校正層的 t2tw 政策已選定「台」             |
| 他→它 | 286  | 議場談法案機關多用「它」                           |
| 嗎→嘛 | 317  | 逐字稿為口語，「嘛」偏高；打字以疑問句的「嗎」為主 |
| 了→瞭 | 108  | 異體字                                             |
| 覆→復 | 51   | 台灣慣用「答覆」                                   |
| 照→召 | 29   | 「謝謝召委」的碎片                                 |

其餘替換（紋→**文**、屬→**署**、按→**案**、人→**仁**、佈→**布**、昇→**升**）為正確修正，保留。`再→在` 與 `在→再` 兩個方向同時存在且皆保留，這正是 bigram 應提供的上下文區分。

曾嘗試以「詞庫預設領先語料選擇超過 0.3 即移除」作為自動判準，經檢視移除清單後放棄：該規則移除的內容幾乎全部落在上述已點名的三類，同時誤殺 `邱+泰源`（落差 0.87，正確的人名消歧）。落差對此問題無區辨力。

### 讀音問題

純文字語料的結構性限制：`build-bigram-stats` 無讀音資訊，只能從詞庫既有的 qstring 中挑選權重最高者。此限制產生兩種失效模式。

**近乎同分的多讀音**。`一行` 在詞庫有 `5_QM` 與 `F0QM` 兩個讀音，權重完全相同（皆 `-0.951576`），挑選結果為任意。語料的「最後一行」為 ㄧˋㄏㄤˊ，但被掛到 ㄧˋㄒㄧㄥˊ，與 `異形` 競爭同一讀音。此類以「該詞所有讀音的權重全距 ≤ 0.1」判定並移除，共 298 列。

其中多數為「一」的變調（一個／一下／一些），掛錯聲調只會使該列不觸發，屬無害；真正有害的是 `一行`、`一體`／`液體`、`長在`／`常在`、`自調`／`字條` 這類讀音對應不同意義且與其他詞碰撞的情形，此類必然出現在複核表中。

**詞庫讀音排序錯誤**。「數」的權重為 ㄕㄨˇ（`|O`，數落／數一數）`-0.930`、ㄕㄨˋ（`\_`，數字／人數）`-1.803`，與實際用法相反。`build-bigram-stats` 取最高權重，於是 預算數／決算數／案件數 等 37 列全被掛到 ㄕㄨˇ，與 屬／署 競爭。

此類無法由規則偵測，同一讀音下 `署`（體育署）掛在 `|O` 是正確的，`數` 是錯誤的，機械上無法區分。修正分兩層：

1. `sources/chiaki-modern-overlay/explicit.tsv` 對調兩個讀音的權重（`reading-order-fix` 標記），使後續 build 直接掛對；
2. 後處理保留 `READING_REMAP` 作為過渡期修正，重新 build 後因比對不到來源讀音而自動失效。

`一行`（ㄧˋㄏㄤˊ）在詞庫中完全缺漏（僅有兩個 ㄒㄧㄥˊ 讀音），屬 unigram 層缺詞，與本層無關。

### 人工複核

自動過濾無法處理的判斷交由複核表。表中列出所有**會改寫該讀音預設候選**的列，附真實例句，依 `doc_count` 排序，並分為三桶：

| 桶       | 說明                                                           |
| -------- | -------------------------------------------------------------- |
| 讀音存疑 | current 有多個近乎同分讀音，配對可能錯誤；應先確認讀音再談其他 |
| 單字差異 | 同長度、差一字；異體字與真消歧混雜，結構上無法自動區分         |
| 其他     | 明確的同音異詞消歧候選                                         |

複核決定以 `keep` / `drop` 記錄於 `review-decisions.tsv`，可在重新產生時沿用；`keep` 會跳過所有後續自動過濾，供個案放行。

### 限制

- 語域偏斜明顯：國防、預算、法案詞彙佔比高，食物、娛樂、購物等日常詞幾乎不存在。本層應定位為補足正式口語與時事詞，不能取代日常語域來源。
- 純文字語料無法提供讀音，破音詞的處理僅能以「移除疑慮列」處理，無法正確歸類。
- 議事語域 denylist 與偏誤字元替換皆為點名清單，需隨語料擴充持續維護。
- 因 API 限流，僅取得索引中 4,037／7,042 份文件。已取得部分在會期分布上不完全均勻。
- 品質評估目前僅能以可達性分類與選材比例衡量，缺乏實際輸入正確率的驗證。`tmp/benchmark/goldset-eval.mjs` 不讀取 bigram，現有 gold set 無法評估本層。
