# ChiaKey 自動熱門詞覆蓋層

## 來源代號

`chiaki-auto-hotwords-overlay`

## 資料層

專案詞庫

## 用途與定位

此來源為自動更新的小型熱門詞覆蓋層。

Google Trends 與 PTT 八卦板都只用於「發現訊號」：每日流程收集 Google Trends 的 24 小時、48 小時、7 天視窗，以及八卦板過去 24 小時內淨推文數至少 20 的文章標題與正向推文彙總訊號。流程會先以 index 頁篩選熱門候選文章，再抓取候選文章的推文數；只保存最小化正規化觀測值為 GitHub Actions artifacts。每週流程再聚合觀測值，只將 ChiaKey 自有的最終覆蓋列寫回本目錄。

此層會隨時間變動，不視為人工審查來源。

## 檔案與格式

`phrases.tsv`：

```text
phrase<TAB>weight<TAB>tags
```

Release builder 會依既有單字讀音推導 qstring；無法推導的列在 release 準備時會被略過。

## Release 匯入規則

自動化策略：

- 正規化後只保留全漢字詞。
- 移除 ASCII 字母與數字。
- PTT 以文章標題、淨推文數與正向推文的彙總訊號產生候選詞；不保存文章內容、推文內容、作者或 IP。標題候選僅取引號中的未知核心、人名、地點／設施名稱，或出現在至少兩個標題的未知短語。
- 推文候選僅計入 `推`，且須為 3 至 4 字、至少出現在十篇文章、累計十五則推文；含常見功能字或純重複字的片段會先排除。artifact 只保存通過門檻的詞、跨文章數、推數、不同推文者數量與最大文章淨推數。
- 只保留 2 到 4 個 codepoint 的詞。
- 移除天氣、股價、目標價、排行、指數等查詢型詞。
- 若事件或路況型查詢詞可由既有詞庫切出明確核心詞與尾詞，會派生核心候選詞；例如 `雪隧路況` 可提供 `雪隧` 訊號，但完整查詢詞仍會被移除。
- 若 5 到 8 字的長熱門詞可由既有詞庫切出未知短片段，會派生 2 到 4 字的未知片段候選詞。
- 移除已存在於基底詞庫的詞。
- 移除已可由既有高排名片段自然輸入的詞。
- 僅出現在 7 天視窗的詞視為弱訊號，不會單獨進入覆蓋層。
- 新詞仍須通過多日／多視窗訊號門檻；一旦入選，state 會保留 180 天，覆蓋層則在最後觀測後最多保留 90 天。

權重策略（保守）：

- `-2.4`：通過多視窗門檻。
- `-2.1`：近 14 天重複訊號更強。
- `-1.9`：近 30 天持續重複訊號。
- `-2.6`：14 天未觀測後進入衰退期。
- `-2.8`：31 至 60 天未觀測的冷卻期。
- `-3.0`：61 至 90 天未觀測的休眠期。

訊號計分：

- `24h`：1 分
- `48h`：2 分
- `7d`：3 分

詞條僅在短視窗有足夠交叉佐證時才會輸出（例如同時出現在 `24h` 與 `48h`、短視窗加 `7d`、或跨多日重複出現）。單一 `7d` 觀測只作背景，不足以新增詞條。

派生核心候選詞會在 tags 中標記 `derived_from=...`，供 PR 審查追蹤來源查詢詞。

## 研究附錄：自動熱門詞蒐集與篩選方法

### 摘要

本附錄記錄 ChiaKey 自動熱門詞覆蓋層的資料蒐集、候選詞萃取與詞條生命週期設計。系統整合 Google Trends 與 PTT 八卦板兩類公開熱門訊號。Google Trends 提供跨來源的搜尋趨勢觀測；PTT 提供高討論度文章標題中的詞彙訊號。兩類資料經正規化、詞庫覆蓋檢查、讀音推導、訊號累積與權重衰退機制處理後，形成可供輸入法使用的動態覆蓋層。

### 研究問題

1. Google Trends 的不同時間視窗如何提供短期與持續性熱門詞訊號？
2. PTT 高討論度文章標題如何補充搜尋趨勢未充分反映的詞彙？
3. 候選詞萃取如何降低標題殘片與短期雜訊的比例？
4. 詞條生命週期如何兼顧詞庫覆蓋率、輸入排序與長期可用性？

### 資料來源與資料最小化

| 來源 | 觀測單位 | 時間範圍與門檻 | 保存資料 |
| --- | --- | --- | --- |
| Google Trends | 台灣地區熱門搜尋詞 | 24 小時、48 小時、7 天視窗 | 正規化詞、流量、成長率、開始時間與視窗標記 |
| PTT `Gossiping` | 熱門文章標題與正向推文彙總 | 執行時間前 24 小時；index 分數與淨推文數皆至少 20；推文詞須跨十篇文章且累計十五推 | 標題衍生詞、發文時間、淨推文數與通過門檻的推文詞彙總 |
| PTT `C_Chat` | 熱門文章標題與正向推文彙總 | 與 `Gossiping` 相同；推文詞須有同篇兩位不同推文者支持，且字形與文章標題對應 | 標題衍生詞、發文時間、淨推文數與通過門檻的推文詞彙總 |

PTT 流程不將文章內文、推文內容、作者或 IP 寫入 artifact 或版本庫。推文會在記憶體中完成候選詞計數後立即捨棄；資料蒐集僅支援候選詞訊號建模，不用於使用者分析、內容再散布或個人檔案建立。

### 訊號整合流程

```text
Google Trends (24h / 48h / 7d) ─┐
                                ├─ 正規化與詞庫檢查 ─ 候選詞 state ─ 訊號累積 ─ 動態覆蓋層
PTT 熱門標題與推文彙總 (24h) ────┘
```

Google Trends 觀測以視窗區分：24 小時、48 小時與 7 天分別給予 1、2、3 分。PTT 觀測標記為 24 小時來源訊號，並保留來源代號，使後續 PR 可辨識 Google Trends、PTT 或兩者的共同觀測。最終詞條須通過既有的全漢字、2–4 字、讀音可推導、基底詞庫未覆蓋與可輸入性等檢查。

### PTT 標題萃取方法

標題萃取方法以多日資料進行評估。README 記錄方法與資料治理原則；樣本數、候選詞與品質比較將於累積足夠觀測期間後另行彙整。

### PTT 候選詞萃取方法

1. 移除 `Re:`、`[新聞]`、`[問卦]`、`[爆卦]` 等標題前綴。
2. 以基底詞庫進行最長詞切分；已由詞庫覆蓋的片段不再作為新增候選。
3. 從引號中的詞組擷取未知核心。例如 `「每月狂燒 9 萬」` 提供 `狂燒` 訊號。
4. 依人名邊界擷取人名。例如 `王凱`、`牛煦庭`、`陳培瑜`；後接敘述的 `王凱驚傳`、`牛煦庭憶` 不納入候選。
5. 從已知行政區後擷取地點或設施核心。例如 `高雄九如橋` 提供 `九如橋`。
6. 一般未知短語須出現在至少兩個不同標題。此規則保留 `怎解` 等重複使用的口語短語，並降低單篇殘片的影響。
7. 同來源、同日、同熱度的兩個四字候選若彼此位移一字且重疊三字，視為同一個五字以上表面的滑動殘片並同時排除。例如「垃圾民進」與「圾民進黨」不會各自累積成詞。
8. 所有候選仍須累積多日或多視窗訊號，才具備輸出至覆蓋層的資格。

### PTT 推文彙總方法

1. 僅處理已通過文章熱門門檻的文章，並僅計入標記為 `推` 的留言。
2. 推文文字只在記憶體中進行 3 至 4 字候選片段計數；含常見功能字或純重複字的片段不進入彙總。
3. 候選詞必須出現在至少十篇不同文章且累計至少十五則正向推文。重疊候選以較長、支持度相近或更高的詞組保留。
4. 彙總完成後僅輸出詞、跨文章數、推數、不同推文者數量與最大文章淨推數；原始推文、推文者識別與時間資訊不會保存。

### PTT 首次入選

PTT 只有 24 小時觀測視窗，無法像 Google Trends 在同一天以 24 小時、48 小時與 7 天多視窗交叉確認。純 PTT 候選除原有的三日重現規則外，也可在十四日內至少出現兩天，且所屬熱門文章最大淨推數至少為 60 時首次入選。這讓跨兩日的高討論度專名有機會進入覆蓋層，同時維持單日高熱度片段不直接入選。

每週 PR 的來源摘要會分來源列出載入觀測數、不重複候選數、帶有該來源訊號的覆蓋層詞數與占比，供持續檢查來源失衡。

### C_Chat 比較研究

`C_Chat` 的詞彙分布包含作品名稱、角色名稱、遊戲機制縮略語與中英混合表記。因此使用獨立來源代號 `ptt-cchat`，不套用八卦板的跨十篇文章門檻。推文候選須至少出現在兩篇熱門文章，並在其中一篇獲至少兩位不同推文者的正向支持；候選字形也必須可由該文章標題覆蓋。抽卡次數、卡池與數值計算句型會先排除。此設計保留作品脈絡詞，同時排除脫離標題情境的遊戲句型殘片。所有候選仍須經既有的跨日訊號、詞庫覆蓋與可輸入性檢查。

### 詞條生命週期

首次入選採用多日／多視窗訊號門檻。入選後，覆蓋層的保留期間為 90 天，state 的保存期間為 180 天。最後觀測後第 31–60 天使用 `-2.8` 權重，第 61–90 天使用 `-3.0` 權重。第 91–180 天的詞條保留於 state，供後續觀測恢復；超過 180 天未出現的詞條會由 state 清除。

此設計以較高的首次入選門檻控制短期雜訊，並以較長的 state 保存期間維持曾入選詞條的再現能力。

### 限制

- Google Trends 與 PTT 分別反映搜尋行為與單一社群的討論行為，兩者皆具有來源偏差。
- PTT 網站可能拒絕 GitHub-hosted runner 的連線；收集失敗時 workflow 僅使用 Google Trends 觀測。長期穩定性可透過自架 runner 或受允許的網路出口改善。
- `C_Chat` 的詞彙分布與 `Gossiping` 顯著不同；目前規則著重漢字詞，含英數的作品名與遊戲術語仍可能漏檢。
- 人名與地點的規則式辨識無法涵蓋完整中文命名實體範圍，罕見姓名與新興詞彙可能出現漏檢或誤判。
- 候選詞數與品質需以多日資料評估；單日觀測不作為長期分布或詞庫規模的依據。
