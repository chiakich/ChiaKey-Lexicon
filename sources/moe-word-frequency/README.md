# 國教院通用詞頻表（排序依據）

## 來源代號

`moe-word-frequency`

## 資料層

校正層

## 用途與定位

此來源只做一件事：**在權重相同的候選之間決定誰排前面**。

walker 取候選時用 `stable_sort`（`LanguageModel::findUnigrams`），穩定排序對相等的元素維持輸入順序，而輸入順序是 SQLite 回傳資料列的順序，也就是資料列在檔案裡的實體位置。因此**權重相同的兩個候選，誰排第一取決於建庫時的實體佈局**——沒有任何語言學意義，且會被任何 `UPDATE` 打亂。

實測規模：同讀音相鄰候選對 68,684 組中有 **12,003 組權重完全相同**。實測影響：兩份內容完全等價、只差資料列順序的資料庫，spoken 語域逐句正確率相差 **1.02 個百分點**——大於本專案多數改動的效果量。

典型案例是 `啦`／`拉`（讀音 `A1`，權重同為 −1.198788）。順序一翻，「就好了啦」就變成「就好了拉」，上千句受影響。

本表提供外部、客觀的頻率依據來決定這個順序。它**不改變任何權重**，只在權重相同時當第二排序鍵。

## 覆蓋率

以「較常見的一方之詞頻」衡量 tie 的實際影響：

| 影響門檻 | 組數 | 可由本表決定 |
| --- | --- | --- |
| ≥ 1/百萬 | 1,408 | **100%** |
| ≥ 10/百萬 | 693 | **100%** |
| ≥ 100/百萬 | 222 | **100%** |
| 全部 | 12,003 | 27.9% |

無法決定的 72.1% 全是罕見字對罕見字（`疽`／`蛆`、`趄`／`麴` 這類），兩邊都不在通用詞頻表中。那些位置維持既有行為。

查不到的詞視為頻率 0：163,701 詞的通用表中沒有收錄，本身即是「極罕見」的證據。`的`(54,604) 對 `篪`(未收錄) 這類判定因此成立。

## 效果

沿用同一批 gold set（`Docs/WalkerBaseline.zh-TW.md`），只改排序、不動權重：

| 語域 | 逐句正確 | Δ |
| --- | --- | --- |
| wiki | 67.43% → 68.79% | **+1.36** |
| forum | 69.62% → 70.41% | **+0.80** |
| casual | 72.98% → 73.62% | +0.64 |
| spoken | 74.83% → 75.25% | +0.41 |
| written | 64.31% → 64.53% | +0.22 |

## 限制：頻率不分讀音

原表是**每個詞一個頻率**，不區分讀音。多音字的總頻率因此會被帶到它的每一個讀音上，包括它其實罕用的那些。

`的` 的 54,604／百萬 幾乎全部來自 ㄉㄜ˙，但這個數字對 `的` 的 ㄉㄧˋ（`:_`）讀音同樣適用。若某組 tie 落在 ㄉㄧˋ 上、對手是以該讀音為主的 `地`，本表會錯誤地把 `的` 排前面。

實測淨效果仍為正（五語域 +0.22 ～ +1.36），因為絕大多數 tie 是「常見字對冷僻字」（`的` 對 `篪`），此時讀音歸屬不影響判定。但**多音字對多音字的 tie 可能被判錯**，這是已知的殘留誤差。

這不是本表獨有的性質，一般詞頻統計都以詞為單位。要真正解決需要逐（詞，讀音）的頻率，目前沒有現成來源。

## 檔案與格式

`frequency.tsv`：

```text
word<TAB>per_million
```

`per_million` 為原表的「每百萬詞頻（平均）」，即書面語、口語、新聞三個語域的平均。原表另有三語域各自的詞頻與序位，本檔未收錄——排序只需要一個數值。

檔案只收錄**同時出現在本專案詞庫與原表中**的詞，99,107 筆。

## Release 匯入規則

在所有 unigram 來源之後、`Mandarin-bpmf-cin` 重排之前執行 `db::reorder_unigrams`，依

```text
ORDER BY qstring, probability DESC, per_million DESC, current
```

重寫 `unigrams` 表。權重不變，只有實體列順序改變。最後一個鍵 `current` 保證兩邊都查不到時仍然是決定性的（雖然是任意的，至少可重現）。
