# 千秋製台灣同音消歧 bigram 語料

## 來源代號

`chiaki-tw-homophone-bigram`

## 資料層

專案詞庫

## 用途與定位

本來源收錄從真實台灣中文文本萃取的 bigram 資料：政府機關新聞發布、立法院公報詢答逐字稿、PTT 與 Plurk 論壇語料，以及正體中文維基百科條文。

本研究的設計前提是：bigram 對注音輸入法的唯一作用，是在使用者實際會打出的那個讀音上，把落後的同音候選推到前面。三個條件缺一不可，若那個詞在自己的常用讀音上本來就是最高權重候選，walker 已經會選它；若把資料列綁到該詞的罕用讀音，使用者永遠不會觸發它；若語料本身顯示同一前文後面另一個同音候選更常出現，這一列就是在跟證據對抗。因此本研究在產生階段即檢查這三件事，並以四個語域的 held-out 輸入正確率作為合併閘門。

本專案只散布最終萃取的詞庫列，原始文本與中間語料均不納入。

## 檔案與格式

`bigrams.tsv`：

```text
qstring<TAB>previous<TAB>current<TAB>probability
```

本來源沒有 `review-decisions.tsv`。資料列由自動判準產生並以 held-out 評估驗證，未逐列人工複核（見〈限制〉）。

## Release 匯入規則

匯入位置在 `openformosa-common-voice-25-zh-tw` 之後、`chiaki-web-overlay` 之前（`src/release.rs` 的 `import_chiaki_tw_homophone_bigrams`）。web overlay 是人工審查過的來源，其判斷應保留在本層之上。manifest priority 為 `310`。

這一層取代了兩個既有 bigram 層，兩者都在 2026-07-29 停用：

| 停用來源 | 停用範圍 | 依據 |
| --- | --- | --- |
| 原 `chiaki-synthetic-overlay` | 已退役並併入 modern overlay | bigram 邊際貢獻零至微負；unigram 保留於 `chiaki-modern-overlay/unigrams.tsv` |
| `tw-ly-transcript` | 整層 | 修掉 65 筆 nq 綁定列之後，邊際貢獻仍是 +0.07%／−0.6%／−0.5%／−0.5% |

`chiaki-web-overlay` 予以保留：邊際貢獻雖為 −0.4%，但它是人工審查層且最後匯入，其判斷是最終仲裁；本研究的評估量不到人工判定所防範的個別體驗問題。

Bigram 以條件強度序匯入，release 階段重新錨定到當前 unigram floor：

```text
stored = min(unigram(current) + boost + (raw - raw_max_of_source), -0.05)
```

- 預設 `boost`：`1.5`
- 覆寫環境變數：`CHIAKI_TW_HOMOPHONE_BIGRAM_BOOST`
- 設為 `0` 時：保留原始數值

`probability` 欄位是這個來源內部的強度序，不是條件機率。數值由 `doc_count` 經 log 映射到`[-1.7, -0.2]`，映射公式跟 `tw-ly-transcript` 相同，讓兩層的強度尺度可以比較。

## 研究附錄：以同音撞碼為單位的 bigram 萃取與驗證

### 摘要

本附錄記錄這個來源的產生方法，以及過程中被推翻的幾個判斷。四個主要結論：

1. bigram 的價值只存在於「使用者會打的那個讀音上會落後」的位置。詞庫 335,427 個詞條裡符合這個條件的有 55,170 個（16.4%）。判準若只檢查「有沒有同音對手」而不檢查「在哪個讀音上落後」，會產出大量永遠不觸發的資料列。
2. 配對必須來自真實文本，不能請語言模型生成或推測。瓶頸不是「哪些詞會撞碼」（那可以從詞庫直接列舉），而是「哪些 `previous`+`current` 真的出現在台灣人寫的句子裡」。
3. 語料證據檢查是搶錯的主要防線，重要性隨語域差很多。在書面語域它帶來約 35% 的淨值差異；在真實訊息語域，它是「有效」與「幾乎無效」的分界（+4,061 對 +34）。
4. 品質必須用多語域 held-out 輸入正確率衡量。單一語域的評估會系統性誤導：本層的前一版在書面語域淨值 +85,128，但在真實訊息語域只有 +65。這套評估工具在開發過程中三度推翻了本研究自己的結論（見〈評估方法的三次修正〉）。

### 研究問題

1. 一筆 bigram 在什麼條件下才會改變輸入結果？如何在產生階段就只保留這些列？
2. 語言模型能不能直接產生可用的 bigram 配對？
3. 在沒有標註資料的前提下，如何量測一個 bigram 層的實際效益與副作用？
4. 訓練文本的語域組成對跨語域表現的影響有多大？

### 選材判準：在常用讀音上落後

對詞庫中每個詞，取其權重最高的讀音（即使用者最可能用來打出該詞的讀音），比較該詞在這個讀音上的權重與同讀音最高權重候選：

| 判定 | 說明 | bigram 效果 |
| --- | --- | --- |
| 無同音競爭者 | 該讀音只有這一個候選 | 無效 |
| 已是最高權重 | 有同音對手，但這個詞已勝出 | 無效 |
| 會輸給對手 | 有同音對手且這個詞落後，需要上下文才能勝出 | 唯一有效 |

用同一個判準檢視各 bigram 來源：

| 來源 | 列數 | 單一候選 | 已是最高權重 | 會輸給對手 |
| --- | --- | --- | --- | --- |
| `chiaki-web-overlay` | 11,196 | 1,855（16.6%） | 4,142（37.0%） | 5,199（46.4%） |
| `tw-ly-transcript` | 7,385 | 2,428（32.9%） | 2,596（35.2%） | 2,361（32.0%） |
| `chiaki-synthetic-overlay` | 46,822 | 11,531（24.6%） | 29,844（63.7%） | 5,446（11.6%） |
| **`chiaki-tw-homophone-bigram`** | **292,639** | **0** | **0** | **292,639（100%）** |

`chiaki-synthetic-overlay` 有 88.4% 的資料列落在不需要 bigram 的位置。該來源產生時尚未建立這個判準，且語言模型生成的文本含相當比例的幻覺詞與虛詞搭配，兩者疊加造成大量無效列。這是本研究重新設計選材判準的直接動機。

這張表的判準跟 `tw-ly-transcript` 研究附錄裡的「有同音對手比例」（73.0%）不是同一個指標：後者計算「該讀音是否存在同音對手」，不要求本詞落後，也不限定於常用讀音。

判準是以當前詞庫權重為準。之後若調整 unigram 權重，原本「已是最高權重」的配對可能轉為落後，需要重新過濾。

### 三條路線的實測比較

本研究先後嘗試三種產生配對的方法，前兩條在評估工具建立之後被判定失敗。

路線一，生成語料後計數。以本機語言模型（`gemma-4-26B-A4B`，MLX 4bit）產生台灣繁體中文短文，斷詞後統計 bigram 頻率。30.5 萬漢字只能產出約 2,000 個落在撞碼位置的配對，長尾頻率估計雜訊極大。按實測速率要達到可用規模需要連續生成數週。而且生成文本有自己的句式偏好（單一 prompt 下「相關單位」在 381 篇中出現 62 篇），直接計數會把模型偏好誤認成語言頻率。

路線二，列舉撞碼詞後由模型補上下文。既然撞碼詞可從詞庫列舉，改為對每個撞碼詞批次詢問模型「最常出現在它前面的詞」，再以模型 logprob 判別式驗證（`logP(current|previous) − logP(rival|previous)`，多載體句平均）。工程效率很高（12 詞／9 秒），一夜可以覆蓋全部 29,221 個高頻撞碼詞，產出 20,092 筆通過驗證的配對。

held-out 評估顯示這條路線失敗：那批資料在 32.6 萬句測試語料中只命中約 200 次。原因是模型推測的 `previous` 幾乎全部落在真實用法之外，可列舉的是撞碼詞，不是配對。判別式驗證能確認「給定這個前文，這個詞是否勝過同音對手」，卻無法確認「這個前文是否真的會出現」。

路線三為本研究採用者：真實文本抽取 + 撞碼過濾 + 語料證據檢查。產生成本是幾分鐘的批次處理。

路線二的判別式打分器保留在研究工具中，其適用位置是過濾真實文本產生的配對，而非發明配對；目前尚未套用於本來源。

### 產生流程

工具與可執行的步驟在 [`pipeline/`](pipeline/README.md)，該文件同時記錄語料取得方式、重建的驗證狀態與已知缺口。以下列出演算法本身。

```text
1. 句切分       全形句讀（。！？；）與換行切句，保留 8 字以上且含漢字者
2. 斷詞         Viterbi 最大分數斷詞，詞長加成 +1.0／字，對齊 walker 評分
3. 配對統計     相鄰詞對，同時記錄 count 與 doc_count
4. 複合詞排除   previous+current 本身是詞典詞者移除（屬 unigram 層）
5. 文件頻率門檻 doc_count >= 3
6. 的/地/得排除 這三字交由輸入法本體以聲調區分，不在本層處理
7. 頭銜姓氏排除 previous 為「立法委員」「立委」且 current 為單字者移除（立法院公報
                的人名偏誤，見下）
8. 撞碼過濾     current 在其權重最高的讀音上必須落後於同音對手
9. 讀音綁定     qstring 綁定該常用讀音；previous 須只有一種讀音，否則棄用
10. 語料證據檢查 同一 previous 之後，語料中不得有任何同音對手比本候選更常出現；
                對手若與 current 構成「同長度差一字」且 previous+對手 是詞典詞，
                視為已具證據（它的計數為 0 是斷詞合併造成的假象）
11. 強度映射    doc_count 經 log 映射至 [-1.7, -0.2]
```

各階段列數：

| 階段 | 列數 |
| --- | --- |
| 抽取全部相鄰詞對 | 24,576,270 |
| 其中複合詞（步驟 4 排除） | 72,565 |
| 非複合且 doc_count >= 3 | 5,409,592 |
| current 在常用讀音上未落後（步驟 8 排除） | 3,895,613 |
| previous 讀音歧義（步驟 9 排除） | 1,027,731 |
| 同音對手在語料中更常見（步驟 10 排除） | 113,750 |
| 的／地／得（步驟 6 排除） | 79,502 |
| 頭銜＋單姓（步驟 7 排除） | 220 |
| **最終產出** | **292,639** |

斷詞採 Viterbi 而非最長匹配，並以 +1.0／字的詞長加成對齊 `ChiaKey Node.cpp` 的 walker評分，使抽取出的詞界與實際輸入時的詞界一致。

步驟 4 依 `bigram-vs-unigram-placement`：`previous`+`current` 構成單一詞的情況屬 unigram層。

步驟 6：輸入法本體將改為「打 ㄉㄜ˙ 出現『的』、打 ㄉㄜˊ 出現『得』」，以聲調區分並交由使用者判斷。這三字共用 `nq` 讀音，在本層以 bigram 處理不但多餘，實測還會互相搶位。

步驟 7 於 2026-07-29 加入，移除 35 列。立法院公報整篇稱謂「立法委員 X」「立委 X」，那個單字是委員的姓，配對頻率反映的是哪幾位委員發言次數多，不是語言裡的搭配關係；姓氏本身也已由 unigram 層處理。四個語域的淨值各降 0～27（書面語域降幅最大，因為政府新聞與公報同屬公共事務語域）。

步驟 10 的第二項判準（整詞假象）於 2026-07-29 加入，移除 10,641 列。成因是：標準寫法若本身是詞典複合詞（像 `電影裡`、`送禮`、`成就`），斷詞會把它合併成單一 token，那個配對在語料中的計數因此恆為 0；而非標準寫法（`電影裏`、`送哩`、`成舊`）不是詞典詞，會被切成兩個 token 並累積計數。步驟 10 原本比較 13 對 0 便予放行，形成系統性偏好非標準寫法。隨機抽樣 22 筆被移除的列，內容為錯字、日文字形（`聖霊`、`新緑`）與簡體字形（`蝴蝶结`）。

這批列實際上不會發動，整詞路徑在詞長加分後勝過「拆詞＋bigram 最大加持」（例如`電影裡` 有效分 0.174 對 `電影`+`裏` 0.159），但它們仍然是體積與雜訊。移除後四個語域的淨值各降約 7%，那個降幅對應的是「使用者刻意打出非標準寫法時能否被救回」，不是一般輸入情境。

步驟 10 的第一項判準是搶錯的主要防線，效果隨語域差異極大：

| 設定 | 列數 | 訊息語域 修對／壞／淨 |
| --- | --- | --- |
| df≥3，不做語料證據檢查 | 251,023 | 5,267／5,233／+34 |
| **df≥3 + 語料證據檢查** | **192,860** | **4,679／618／+4,061** |

（上表是凍結前的 95% 訓練版本，見〈評估協定〉。）

### 測試後未採用的過濾規則

以下兩項在四個語域都讓淨值下降或持平：

| 追加過濾 | 訊息語域淨值 | 判定 |
| --- | --- | --- |
| 基準（步驟 1–10） | +4,061 | — |
| 再排除單字＋單字配對 | +2,159 | 否決 |
| 再排除 t2tw 異體字對 | +4,060 | 否決（持平） |

單字配對佔剩餘搶錯的多數（人名與量詞碎片），但它們修對的位置更多。`src/bigram.rs` 內建的 `is_single_char_pair` 排除規則在真實文本資料上不成立，已於同批變更中移除該排除條件（stats 欄位保留以維持可觀測性）。

t2tw 異體字對只有約 100 列，而且台→臺 與 臺→台 兩個方向同時存在，顯示這類選擇取決於文件用字慣例而不是上下文，bigram 結構上無法裁決；應該由校正層的 t2tw 政策統一處理。

### 評估方法

在真實文本上斷詞，逐個相鄰詞對判定。判定對齊 runtime 行為：一筆資料列只在使用者打出該列 qstring 所編碼的讀音時才可能生效，且必須勝過 unigram 排頭。評估重播 release 的calibration（`boost` = 1.5），僅計入 C 類（恆生效）資料列。

- 可修位置：`current` 在它的常用讀音上落後，也就是沒有 bigram 時 walker 會選錯
- 修對：overlay 含該 `(previous, current)`，綁定讀音相符，而且校準後分數勝過排頭
- 搶錯：`current` 原本已勝出，但 overlay 含同一讀音下另一候選與同一 `previous` 的配對

### 評估協定

演算法先在四個語域上調校並凍結，之後才以全部語料重建出貨版：

| 測試集 | 內容 | 句數 | 可修位置 | 角色 |
| --- | --- | --- | --- | --- |
| 書面 | 新北市政府新聞（後半） | 326,069 | 952,140 | 開發集 |
| 口語 | 立法院公報 11-2 會期 | 74,304 | 84,069 | 開發集 |
| PTT | PTT 語料 5%（按篇抽樣，涵蓋 169 板） | 156,656 | 461,649 | 開發集 |
| 訊息 | 作者與朋友的群組對話（按日切半） | 70,463／73,701 | 31,523／34,445 | dev／凍結 |

訊息語域測試集來自一份群組匯出檔，為作者與其朋友的群組對話，成員皆已同意作為benchmark 使用，該語料僅用於量測，不進入訓練，亦不在本專案散布。處理時丟棄發言者欄位、移除系統與媒體訊息、移除網址、遮蔽三位以上英數字串。

凍結驗證（df≥3，95% 訓練版本，僅檢視一次）：

dev 與凍結半的修復率（14.8% 對 14.5%）與搶錯率（13.2% 對 13.0%）幾乎相同，沒有過擬合的跡象。

出貨版（100% 語料訓練，292,639 列）在四個語域：

| 書面 | 962,387 | 349,391 | 17,250 | +332,141 | 36.3% |
| 口語 | 85,240 | 23,569 | 1,824 | +21,745 | 27.7% |

同協定（全語料訓練）與重建前相比：書面 +2,041、口語 +2,776、PTT −123。

### 評估方法的三次修正

本研究的評估工具在開發過程中有三個錯誤，每次都造成對成果的高估，記錄於此供後續參考。

一、資料列被綁到罕用讀音。初版選擇「權重落差最大的讀音」作為 qstring 綁定目標，理由是落差越大越需要 bigram 幫助。這個設計系統性地選中每個詞最罕用的讀音，例如「的」被綁到`:_`（ㄉㄧˋ，權重 −3.09）而不是 `nq`（ㄉㄜ˙，−0.58）。初版 93,952 列中有 68.5% 綁在非常用讀音上。修正為綁定權重最高的讀音。

二、評估忽略 qstring 與 calibration。初版僅比對 `(previous, current)` 文字，等於假設一筆bigram 在該詞的任何讀音下都生效、且必定勝過 unigram 排頭。修正為以`(previous, current, 綁定讀音)` 三元組比對，並重播 release calibration、僅計入 C 類。兩項修正合計使書面可修位置基數由 1,839,565 降至 952,140。

三、測試集語域單一。前一版僅以政府新聞與立法院公報評估，據此得到「書面 +85,128」的結論並已寫入來源文件。加入真實訊息語域後才發現該版本在此語域只有 +65。另曾使用 HuggingFace`iddle/dcard_conversations` 作為日常語域代表，抽樣檢視後發現其內容幾乎全為時事政治討論、與新聞語域高度重疊，不具代表性，已棄用。

以前述舊指標得出的比較結論都不可引用。

可達性分類（`Docs/WalkerScoring.zh-TW.md` 的 A／B／C／D，`boost` = 1.5）。下表與上表的「綁定常用讀音」量在步驟 7 之前的 231,028 列上測得，35 列的差異不影響佔比：

| 類別 | 列數 | 佔比 |
| --- | --- | --- |
| A 不可達 | 0 | 0% |
| B 永不勝出 | 15,358 | 6.6% |
| C 恆生效 | 105,382 | 45.6% |
| D 條件生效 | 110,288 | 47.7% |

C 佔比偏低是選材判準的直接後果：`boost` = 1.5 決定了 bigram 最多能翻多大的權重落差，而本層刻意收錄落後的配對，落差超過 1.5 者只能落在 D（需使用者學習過較弱候選）或 B。反過來說，其他來源的高 C 佔比多半來自「`current` 本來就是該讀音第一名」的資料列，這類列雖然恆生效但不改變任何結果。因此 C 佔比不可單獨作為品質指標。

B 類 15,358 列依 `Docs/BigramPruning.zh-TW.md` 可安全剪除，尚未執行。

### 限制

- 報告的數值來自 95% 訓練版本，出貨檔案是 100% 訓練版本。演算法凍結後才以全部語料重建，因此出貨版未經獨立量測。以「加入 10 個休閒板」的對照實驗估計，額外語料帶來的差異約 +6.5%，方向是改善。
- 評估未計入使用者學習，僅計入 C 類。D 類（110,288 列）是使用者學過較弱候選之後才生效的救援路徑，貢獻取決於個別使用者狀態，無法以靜態語料量測，因此表上數值為下限。
- 斷詞即真值的循環風險。評估以本專案的 Viterbi 斷詞判定「使用者原本要打什麼」，若斷詞與實際 walker 行為不一致，效益會被系統性誤估。
- 詞庫回饋循環。`normalized/smart-mandarin.tsv` 由 release 流程產生，這一層匯入後它的joined-phrase unigram 會回頭改變詞庫，進而改變撞碼判定。實測影響是 952,145 → 952,140個可修位置（0.0005%），不影響結論，但概念上評估已經含了自身的影響。
- 訊息語域測試集有人名偏誤。那個群組成員的名字造成最大宗搶錯（單一對佔全部搶錯 16%）。換一個群組會是不同的名字，所以絕對搶錯數偏高，方向性結論不受影響。
- 訊息語域測試集規模有限（單一群組、3.4 萬個可修位置），且其凍結半已使用一次。後續若再修改演算法，需要新的凍結語料。
- 未逐列人工複核。292,639 列由自動判準產生並以 held-out 評估把關。
- 多音字前文被整批棄用。767,923 筆因為 `previous` 讀音歧義而棄用，其中含相當比例的高頻單字前文。用讀音消歧補回這批資料是明確的改善方向。
- 這一層的效益受 unigram 層品質牽制。詞庫含約 6,300 個 rime-essay 衍生的組合式條目（`電影裡`、`適當的` 這類「已知詞＋方位／虛詞」），其中 291 個在自己的讀音上壓過其他候選（像 `適當的` 壓過 `適當地`、`集中了` 壓過 `擊中了`）。這類條目讓整詞路徑勝出，bigram 層無從介入；清理 unigram 層是獨立而且優先度更高的工作，清理之後這一層需要重新產生。
